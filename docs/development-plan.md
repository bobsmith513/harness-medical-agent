# 开发计划：里程碑设计取舍

> 本文档记录 harness-medical-agent 各里程碑（M0–M8）的设计决策与取舍。
> 与 README 的路线图不同，这里聚焦"为什么这样设计"而非"做了什么"。
> 关键实现参数的具体数值与数据口径见 [design-decisions.md](design-decisions.md)。

## 总体设计立场

在动工之前先定下三条不可协商的原则，所有里程碑的取舍均由此推导：

1. **fail-closed 优先于可用性**：任何不确定状态（解析失败、置信度不足、
   依赖缺失）一律拦截或转人工，绝不静默降级为"继续回答"。
   宁可演示时尴尬，不可线上时沉默放行。
2. **零依赖可运行**：不安装任何可选依赖（Milvus / Redis / BGE / Langfuse）
   时，全链路必须可用——用内存实现与哈希嵌入替代，且**接口不变**。
   这让评审者 30 秒内可以跑通 demo，也让测试套件不依赖外部服务。
3. **主 Agent 永不应答**：编排层没有"自己回答"的能力（类型层面锁死），
   只能路由给专家或升级转人工。这杜绝了"编排层越权编造"这一整类风险。

## M0 工程基座

**取舍**：src-layout + uv + ruff（line-length=100）+ pytest。

- 选 src-layout 而非平铺：防止测试误导入未安装的本地包。
- 选 pydantic-settings 而非手写 env 解析：类型校验 + 嵌套配置
  （`HARNESS_RETRIEVAL__RRF_K` 自动映射）免费获得。
- CI 三 Python 版本矩阵（3.10/3.11/3.12）+ 20 分钟超时 +
  覆盖率门禁：防止"绿了但没跑完"与"绿了但没测到"。

## M1 领域模型与接口契约

**取舍**：先冻结数据模型与协议（Protocol），再写实现。

- `RouteDecision` 设计为三值枚举（`need_reasoning` / `no_reasoning` /
  `escalate`），且 `escalate` 只能由路由器内部失败路径产生——
  LLM 不允许自报"我要升级"，防止模型用升级逃避裁决。
- 所有可审计对象（`Evidence` / `ReasoningChain` / `GateVerdict`）
  均为 pydantic 模型：序列化落库免费，字段缺失即校验失败。
- `Memory.can_be_recalled()` 把"是否可召回"内聚到模型层，
  检索层无需记忆状态机的知识。

## M2 供给层：硬规则与三道闸门

**取舍**：过敏拦截放在最前面，且不经过 LLM。

- 输入闸门（关键词/词典硬匹配）优先于一切：阿莫西林 vs 青霉素
  交叉过敏这类**已知风险**不该消耗一次 LLM 调用。
- 闸门顺序：输入闸门 → 装配闸门 → 输出闸门。输入闸拦问题，
  装配闸拦证据（过敏药物证据不得进入推理输入），输出闸拦结论
  （格式与引用校验）——三道闸各司其职，不重复检查同一层面。
- 词典归一化（品牌名→通用名，如"再林"→"amoxicillin"）在闸门
  之前完成，否则品牌别名会绕过通用名词典。

## M3 供给层：混合检索与记忆隔离

**取舍**：RRF 融合 + 患者分区隔离作为检索层的安全底座。

- 混合检索（稠密 + 稀疏 + RRF 融合）而非单路：稠密路捕捉语义近似、
  稀疏路捕捉词面精确命中（药品名、检验值），两路共识上浮。
- **患者分区隔离**实现为结构约束而非过滤条款：BM25 的 IDF 统计量
  只来自本患者可见分区（跨患者语料规模不泄露），向量存储的搜索
  scope 锁定 patient_id。这比"查出再过滤"强——统计量本身不越界。
- 零依赖默认：哈希嵌入（确定性、L2 归一化、无语义能力——诚实标注
  "无语义能力"而非伪装成向量检索）+ 内存向量存储 + 本地 BM25。
- Milvus 过滤表达式使用白名单转义（`_filter_literal`），
  阻断过滤注入。

## M4 主 Agent 编排与 fail-closed 路由

**取舍**：规则前置 + LLM 兜底 + 误判二次路由。

- 路由器二值输出（`need_reasoning` / `no_reasoning`），
  解析失败/非法值视为误判 → 二次路由（纠错提示更强）→
  仍失败 → escalate。**没有"直接回答"出口**。
- LLM 兜底输出 JSON 用括号深度扫描解析（`extract_json_object`），
  而非贪婪正则 `\{.*\}`——多段 JSON 输出不再跨段误匹配。
- 会话上下文只保留最近 3 轮（`SessionContext.add_turn(keep=3)`），
  溢出旧轮持久化至 VFS——这是长会话 Token 压缩的实现载体。

## M5 推理专家与质量门禁

**取舍**：规则前置（零 LLM 开销）+ LLM-as-judge 兜底。

- 质量门禁两路并行：先跑规则检查（引用真实性、因果正向、
  依据充分性——这些是结构问题，不需要 LLM），规则全过
  才调用 judge LLM 打忠实度分。结构错误拦截不花一次 LLM 调用。
- judge 输出解析 fail-closed：解析失败、字段缺失、类型异常
  一律按拦截处理（faithfulness 视为 0.0）。
- 布尔解析注意 `bool("false")` 为真的 Python 陷阱——
  字符串 `"false"` 显式按假处理。

## M6 VFS 与记忆审核

**取舍**：模型推断不得直接固化为可召回事实。

- 记忆生命周期：`session_pointer` → `pending_review` →
  `approved`（可召回）/ `rejected`（不可召回）。
- 自动审核仅放行 `doctor_verified` + `high confidence` 的记忆；
  `model_inference` **必须人工审核**——这是阻断幻觉记忆
  固化为检索事实的核心安全门。
- 未审核记忆仅作会话内指针，`can_be_recalled()` 返回 False，
  绝不进入检索结果。

## M7 沙箱与可观测

**取舍**：每个外部组件都提供内存默认实现 + 统一降级语义。

- 脱敏中间件（正则 PII 识别）先于一切外部调用：审计与 LLM
  输入均为脱敏后文本。
- 缓存 / 分布式锁 / 审计存储 / tracer 全部遵循同一模式：
  内存实现为默认，Redis / PostgreSQL / Langfuse 按配置注入，
  Redis 客户端构建统一走 `try_redis_client`（依赖缺失返回
  None 而非抛异常，降级路径可测试）。
- 沙箱运行时：Mock（默认，静态证据）与 OpenSandbox（可插拔）。

## M8 端到端演示与完整文档

**取舍**：demo 必须诚实标注 mock 边界。

- 白盒日志走读三个例子（初诊推理 / 复诊记忆命中 / 门禁拦截转人工）
  全部使用静态证据与脚本化 LLM 应答——README 明确标注，
  不伪装成真实 LLM 输出。
- 对抗样本从 7 条扩展到 30 条（品牌别名、剂型绕过、混合请求、
  编码变体等），但**明确限定范围**：这是词典与规则闸门的
  回归测试集，不是 LLM 越狱基准。

## 测试策略（贯穿所有里程碑）

- **依赖反转**：所有 LLM 依赖注入 `MockLLMClient`（脚本化应答），
  测试零外部依赖、确定可重复。
- 测**语义**而非测实现：患者隔离测"跨患者召回无从谈起"，
  fail-closed 测"解析失败必拦截"，而非断言某个内部变量。
- 诚实标注测不到的部分：LLM 真实输出质量、真实 BGE 语义质量、
  真实 Redis 并发——README"测不到的部分与补位方案"一节列出。
